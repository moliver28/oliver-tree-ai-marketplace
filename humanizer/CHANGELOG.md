# Changelog

## [1.2.0] - 2026-11-26
### Added
- Advisory voice-fit table (`learn/voice_fit.py`): the two count-based stylometry layers promoted into one advisory unit, Burrows' Delta (the acceptance_check.py Signal A math) plus the surface statistics (the build_voice_profile.py stats), with the sitefactory P18 refinements: fail-open with no client reference (exit 0, n/a columns and a defined note; bad usage alone exits 2), one actionable row per metric (sample column vs candidate column), the leave-one-out sample-self delta (n/a under 3 sample documents: delta needs spread), and the length confidence note (the cited lengths, Burrows 2002 and Eder 2015, cover attribution among candidate authors, a different task; delta rows read n/a below the owned 500-word floor; never a gate at any length). Reuses `WORD_RE`/`SENT_SPLIT`/`PASSIVE_RE`/`INTENSIFIER_RE`/`FUNCTION_WORDS` from `build_voice_profile.py` (the tokenizer charset the gate's STE layer counts). stdlib only; no embeddings, no perplexity, no classifier. Advisory only: it never runs in the delivery gate.
- Measurement battery, Tier A (`learn/voice_battery.py`, `learn/voice_battery_core.py`, `learn/voice_battery_report.py`, `/voice-fit` command): the 74 rows of the measures map section 3a plus the 5 rows of the methodologist's re-tier pass (delta1), 79 rows total, in one shared pass (one split, one tokenize, one dictionary lookup per token, one small pattern per phrase alternative; no diversity index and no profile distance on the gate path). The battery measures 11 levels: orthography, lexis, morphology, syntax, cohesion, discourse, register, information structure, tone, machine-pattern markers, and distance. Closed lists only: R0/R1, about 5.6 KB, one row per list in PROVENANCE.md; no packages, corpora, models, or VADER-derived data ship (D1b rejects R2); no public norms, bands come from the user's own profile.
- Gate fast core: `hooks/gate.py` lazy-imports `learn/voice_battery_core.py` (the small module; the full battery sits outside the gate's latency budget) and flags the 20 L10-1 marker words it does not already carry. A battery finding occupies at most one of the at most 5 family-deduped fail lines, never a sixth; the clean pass line stays byte-identical.
- On-demand gestalt report (`/voice-fit <file>`): one block per level with inside / near the edge / outside counts and the level band, one edit-class sentence per row (edit classes: sentence length, word choice, punctuation, structure, links, tone, machine patterns, no edit), the overall band, and the length confidence note (suppressed measures listed by name, rank false alarm 1/(k+1) stated). Bands follow the map's comparison math: mean and sample deviation with the t prediction factor, the count floor s_eff = sqrt(s^2 + r * 1000 / N), the paired leave-one-out rank rule on the Jensen-Shannon distance with its false alarm, and per-level holdout outside counts. No decimal fit score; the report is a human-only surface, so the token law holds.
- Profile extension (measure-once / apply-cheap core): `build_voice_profile.py` runs the battery over each sample document and stores per-measure mean, sample deviation, minimum, maximum, and the document count k, plus the pooled reference rows, the per-level holdout counts, and the rank vector in `learned/profile.json` (`battery` section). The report path reads bands from there instead of re-measuring the samples.

### Changed
- Re-tier rows (delta1, one follow-up commit): `L2-5` MATTR (moving-window type-token ratio, window 50 per Kendro et al. 2025, the prototype's 100 superseded), `L10-15` excess-vocabulary rate (the 291-word rare style list of Kobak et al. 2025, figure S6, shipped R1 with a PROVENANCE row), `L11-2` Cosine Delta (cosine between the z-scored document vectors, Evert et al. 2016 section 1, the Smith and Aldridge 2011 definition; rides the function-word loop), `L7-6` function-word PCA projection (offline power iteration with deflation at build time, apply under 0.05 ms, `learned/<profile-stem>-pca.json`, R3 user-local, nothing ships, 5-document minimum), and `L11-11` full-covariance Delta (Cholesky of the shrunk covariance, alpha 0.1 the owner-approved value, forward substitution at apply, `learned/<profile-stem>-covariance.json`, R3 user-local, words with zero variance drop from the solve, leave-one-out distance band stored so the report can place the candidate by rank). Golden tests: fixed correlation matrix in, pinned eigenvector and pinned projection out; fixed covariance in, pinned Cholesky distance out; shrinkage stability at k = 30; MATTR window 50 and the 291-word list pinned. the standardization uses the sample deviation, divide by k minus 1 (was population stddev); the denominators carry the count floor s_eff = sqrt(s^2 + r * 1000/N); a delta with no function-word spread reads n/a, never 0.0 (zero was the best score); the sample-self row prints k and the leave-one-out minimum and maximum next to the mean; delta rows are suppressed below 500 candidate words and compared in windows of the median reference length outside 0.5 to 2 times that length; the length note states the task and the source next to each cited number.
- Battery contract suite `humanizer/tests/test_voice_battery.py`: 79-row spec pins, closed-list size pins (deterministic, never a timing assert), tokenizer sync pins across the three modules, band-math pins, battery goldens on a synthetic corpus (SHA-256 of the rounded value row, run on Python 3.11.15), profile battery-section pins, gate fast-core pins (one battery fail line, byte-identical pass line), report shape pins (11 level blocks, no decimal fit score, fail-open, byte-identical reruns), stdlib-only import pins.
- `scripts/verify.py` enforcement: version parity at 1.2.0, `voice_fit` and `voice_battery_report` importable with `main()`, the deterministic voice_fit check block (fail-open table, profile-mode delta with the owned-floor n/a for short candidates and a float for a 600-word candidate, small-sample n/a spread rule, contract suites for voice_fit and voice_battery), and the acceptance_check JSON row reading null when the profile has no spread.
- Versions bumped to 1.2.0 in `plugin.json`, `plugin.yaml` and the marketplace entry; README humanizer row, LEARN-VOICE.md stage 6 and the PROVENANCE.md origin rows updated in the same edit.

## [1.1.0] - 2026-11-21
### Added
- Tier 1, attraction-side embedding scores (issue #127): `learn/voice_vector_build.py` also persists the user's clean-corpus voice centroid (`learned/voice-centroid.json`, per-document chunk embeddings, optional per-channel centroids via `--channel`); `hooks/voice_tells.py` gains `voice_fit`/`vector_scores`/`vector_pass` computed inside the same single embedding pass as the tell scan (one embed per unique text per process, shared memo). Hash guard: with unchanged corpus/exemplar/background hashes the build prints `current (hash <12 chars>), nothing rebuilt` and exits without loading the embedder.
- Source-fidelity check: `hooks/gate.py --source FILE` reports `source_fidelity` (cosine of source vs rewrite embedding); the source embedding is disk-cached, hash-keyed and bounded (`learned/embed-cache.json`, max 64 entries, oldest dropped, atomic write), so a repeated /voice run on the same draft does not re-embed the source. /voice status line becomes `voice: pass (fidelity 0.91)` / `voice: N fixes applied (voice-fit 0.72)` when the signals exist.
- Tier 2, trained authorship classifier (issue #127): `learn/train_voice_classifier.py`: character 3-5-gram hashing trick (2^16 buckets, md5, log-tf, L2-normalized) + pure-Python offline SGD logistic regression (fixed seed, deterministic order, lr 0.1 with decay, 8 epochs, early stop on loss plateau, class-balanced weights). Trains on the user corpus (weight 1.0) + edit-confirmed texts (weight 0.5) against pre-edit deliveries + a deterministic synthetic AI-prose seeder (200 docs, zero personal content). Writes `learned/voice-classifier.json`; the gate exposes `p_ai` + `voice_delta` as advisory fields (fail-open, never blocking in 1.1.0); hash guard prints `nothing retrained` on unchanged inputs.
- Tier 2, post-hoc edit learning (owner ruling, issue #127): /voice records every delivery in `learned/deliveries.log` (`date`, `sha256(delivered)`, `target`); the new `/voice learn-edit <edited-file> <delivered-original>` command (core in `learn/edit_learning.py`) matches the delivery hash, measures the edit with difflib, and files it: >15% changed -> `learned/edit-delta/{before,after}/` pair (classifier retrain pending), <=15% -> durable light copy + `learned/clean-corpus-index.txt` entry (`edit-confirmed`). calibrate.py scans index entries too; the centroid builder and the classifier trainer consume the same index, hash-guarded.
- Tier 3, offline acceptance check (issue #127): `learn/acceptance_check.py`: Signal A Burrows' Delta over 60 hardcoded function words z-scored against the new `function_words` section of `learned/profile.json` (stdlib, zero setup); Signal B optional `--backend onnx` local GPT-2 small perplexity + burstiness (onnxruntime + model files in `learned/models/gpt2-onnx/`, setup estimate 3-6 min documented, defined absence line + exit 2). Never in the delivery gate; plain-number table or `--json`.
- `scripts/verify.py` enforcement for all of the above: no-rebuild/no-retrain proof without any embedder, deterministic gate advisory fields, classifier training/determinism/empty-input, learn-edit classifications, acceptance-check paths, 1.1.0 version parity.

### Changed
- `voice_vector_build.py` chunks the calibration background per document (the same chunks the centroid consumes), so one embedding pass truly serves exemplars, calibration and centroid; thresholds may shift slightly on rebuild (per-user artifacts).
- `voice_tells.py` exposes the per-user `learned/` directory via `VOICE_LEARNED_DIR` (same override contract as `VOICE_RULES_STATE`/`VOICE_GATE_LOG`) and writes artifacts atomically.
- Manifests/docs updated for the new artifacts, flags and commands; versions bumped to 1.1.0 in `plugin.json`, `plugin.yaml` and the marketplace entry.

## [1.0.0] - 2026-11-21
### Added
- Canonical consolidation: the plugin is now self-contained. The detection core moved from the separate voice-gate plugin into `hooks/voice_tells.py`, the standalone scanner into `hooks/voice_check.py`, and the gate loads its scanner from its own directory.
- Zero-LLM learn tools in `learn/`: `build_voice_profile.py` (deterministic voice profile + onboarding draft from writing samples), `calibrate.py` (per-pattern hit rates over a clean-writing corpus, writes `learned/calibration.json`), `distill_phrases.py` (recurring request phrasings from `learned/phrases.log` into `learned/rules.json`), `voice_vector_build.py` (per-user exemplar vectors + calibration into `learned/`).
- `learn/LEARN-VOICE.md`: the procedure doc (install, onboard, initial learn, enforce, continuous learn) with the explicit zero-model statement per stage and the decide-by-hand conflict rule.
- Runtime hook adapters documented in `hooks/HOOKS.md`: surfaces come from the user's learned profile, never from hard-coded path lists.
- De-personalization: every personal voice artifact left the public mirror. The machine register is the pattern list in `hooks/voice_tells.py` (55 patterns, synthetic exemplars); vectors and calibration are per-user `learned/` artifacts built by the learn tools, no longer shipped.
- LinkedIn post pipeline folded in from the linkedin-style-learner skill, de-personalized: `learn/linkedin/` (renderer, voicebook checker, lever check, templates, synthetic briefs, verification battery with regenerated goldens). Factory link allowlist default is example.org, config-driven.

### Changed
- Description and surfaces updated for the three-stage canonical contract (learn via the deterministic tools, hooks self-contained, `/voice` applies).
- `/voice --dry` and the onboarding pointer now reference `learn/VOICE_ONBOARDING.template.md`.

### Removed
- The separate voice-gate plugin entry; the owner's personal voice skill, register, exemplar vectors, calibration, and the real article briefs (all archived privately outside this repository).
