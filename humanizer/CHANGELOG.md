This release ships the wave H-C entries that sat unreleased below plus the
wave G6 passive harvest loop; the version steps once for the combined
payload. Stacked PR: G6 builds on the open H-C branch (PR #175). The release

will be created for them.

### Added
- The passive harvest loop (wave G6, consent-gated, default OFF): `hooks/harvest.py` appends accepted final drafts to the user's own local reference pool and rebuilds every derived measurement mechanically. The hook runs only when `<learned>/state/setup.json` carries `harvest.enabled = true` AND an `accepted_dir` (with `accepted_glob`, default `*.md`, and an optional `situation` tag); with the flag off or half-configured it reads one settings file and exits 0: nothing runs, nothing logs. Nothing harvested is ever transmitted anywhere; it stays in the learned-state chain under the `VOICE_REFERENCE_DIR` chain and never enters the repo, the payload, a test, or CI.
- Wave G6 wiring: session-end mode (no arguments scans the configured accepted directory, sorted) and document-acceptance mode (`--file PATH`, which must stay inside the consented directory); exact sha256 duplicates skip silently (idempotent append); every appended pool vector gains the provenance row (source `harvest`, UTC timestamp, word count, situation tag); an accepted draft under the battery's 500-word document floor skips with one line.
- Wave G6 mechanical rebuild: after pool growth the hook calls the shared `rebuild_pool()` body of `learn/regenerate.py` (the data-contract pass), so the hook and the scripted pass cannot drift: stale pool vectors recompute from the stored text and the bands rebuild from the refreshed vectors into `learned/state/voice-bands.json`. Pure compute: zero model tokens, no distill pass, no network; deterministic (the same pool state gives byte-identical derived artifacts, pinned by test). An older install without the regenerate pass prints one notice line and skips: fail-open, never an error.
- Wave G6 advisory-first band refresh with the re-approval gate: the refreshed bands are advisory rows and update silently. The `aphorism` band joins the learned-state chain as the ONLY band kind the gate maps into a fail line (a budget override: `max_per_section` / `max_per_piece`, whole numbers of at least 1; `learn/voice_battery_core.py resolve_budget`); a budget candidate derived from the pool lands ONLY as a pending row in `learned/state/band-approvals.json` with the candidate, the active numbers, and a plain-words note. The candidate statistic follows the athena methodology ruling (binding Q1, 2026-11-28): the observed pool maximum shrunk toward the active budget with the plugin's own k/(k+5) shape (k=5, the voice_setup N0=5 law), rounded up, floor 1, per grain derived independently; the raw maximum rides the pending row beside the shrunk number, and the note carries the pool-size tier (start value under 10 drafts, tracks most from 10, tracks nearly all from 30). `hooks/harvest.py --approve-bands` is the explicit promotion: it writes the approved numbers into the runtime state file under the source `harvest-bands` (a DATA write per the issue #5 contract) and clears the pending row; until then the old budget stays active.
- The G6 contract suite `tests/humanizer/test_g6_harvest.py` (consent gate, provenance append, idempotent skip, deterministic rebuild, advisory-silent refresh, the full approval flow at the gate level, harvested-marker privacy over every tracked file, `resolve_budget` rules, stdlib-only module scope, the byte-identical pass line) and verify.py rule 15 (the default-OFF subprocess proof, the budget-band gate proof, the repo-wide privacy scan); the version parity pin moves to 1.5.0 with the manifests.

## [1.3.0] - 2026-11-27
### Added
- The install experience (`/voice-setup`, `learn/voice_setup.py`, `learn/voice-setup.md`): the setup program is the installer. Step 1 measures the machine one time (interpreter spawn, the gate command at a fixed 2,000-word fixture, the battery at 500 / 2,000 / 5,000 words, the fast core, the two axis applies, the level-3 piece) into `learned/state/machine-bench.json`; every number is measured, none estimated. ## [1.1.0] - 2026-11-21
### Added
- Tier 1, attraction-side embedding scores (issue #127): `learn/voice_vector_build.py` also persists the user's clean-corpus voice centroid (`learned/voice-centroid.json`, per-document chunk embeddings, optional per-channel centroids via `--channel`); `hooks/voice_tells.py` gains `voice_fit`/`vector_scores`/`vector_pass` computed inside the same single embedding pass as the tell scan (one embed per unique text per process, shared memo). Hash guard: with unchanged corpus/exemplar/background hashes the build prints `current (hash <12 chars>), nothing rebuilt` and exits without loading the embedder.
- Source-fidelity check: `hooks/gate.py --source FILE` reports `source_fidelity` (cosine of source vs rewrite embedding); the source embedding is disk-cached, hash-keyed and bounded (`learned/embed-cache.json`, max 64 entries, oldest dropped, atomic write), so a repeated /voice run on the same draft does not re-embed the source. /voice status line becomes `voice: pass (fidelity 0.91)` / `voice: N fixes applied (voice-fit 0.72)` when the signals exist.
- Tier 2, trained authorship classifier (issue #127): `learn/train_voice_classifier.py`: character 3-5-gram hashing trick (2^16 buckets, md5, log-tf, L2-normalized) + pure-Python offline SGD logistic regression (fixed seed, deterministic order, lr 0.1 with decay, 8 epochs, early stop on loss plateau, class-balanced weights). Trains on the user corpus (weight 1.0) + edit-confirmed texts (weight 0.5) against pre-edit deliveries + a deterministic synthetic AI-prose seeder (200 docs, zero personal content). Writes `learned/voice-classifier.json`; the gate exposes `p_ai` + `voice_delta` as advisory fields (fail-open, never blocking in 1.1.0); hash guard prints `nothing retrained` on unchanged inputs.
- Tier 2, post-hoc edit learning (owner ruling, issue #127): /voice records every delivery in `learned/deliveries.log` (`date`, `sha256(delivered)`, `target`); the new `/voice learn-edit <edited-file> <delivered-original>` command (core in `learn/edit_learning.py`) matches the delivery hash, measures the edit with difflib, and files it: >15% changed -> `learned/edit-delta/{before,after}/` pair (classifier retrain pending), <=15% -> durable light copy + `learned/clean-corpus-index.txt` entry (`edit-confirmed`). calibrate.py scans index entries too; the centroid builder and the classifier trainer consume the same index, hash-guarded.
