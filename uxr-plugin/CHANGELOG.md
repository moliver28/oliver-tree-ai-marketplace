# Changelog

All notable changes to uxr-plugin. One `## X.Y.Z` heading per release, newest first.

## [0.7.0] - 2026-11-23

### Added

- Tracking web app routes (#91): the Google mail-merge engine `google/mail-merge.gs` (authored in this repository; the architecture is informed by Google's Apache-2.0 mail-merge sample, and no code is copied) serves one web app deployment with three routes. The open pixel (`?o=`) logs an open estimate. The click route (`?c=`) wraps every tracked link, logs the click, and then sends the reader to the target. The unsubscribe route (`?u=`) marks the recipient unsub and returns a confirmation. Each hit appends one row (date, route, email, study, target, note) to the Tracking tab. The SETUP doc `google/README.md` maps the script into the Sheet, deploys the web app, and states the tracking limits.
- Event-timed follow-ups with optional meeting prep (#92): one recurring trigger (`syncEvents`) scans the configured calendar every 15 minutes. An event whose title matches `event_regex` creates a follow-up `followup_hours` after its start, and the send path stamps it. With `prep_on`, the script also creates a Prep row `prep_lead_hours` before the start and emails the prep brief. A deleted or renamed event cancels its pending follow-up and prefixes its prep row.
- Scheduled sends: `scheduleSend(tab, when)` installs a one-off time trigger, so a wave goes out near the requested time without anyone at the keyboard. Google picks the exact minute inside its hourly window, and the trigger deletes itself after it fires.
- Screener to booking confirmation: `setupScreener` builds the screener Form and writes `Book your session: <booking_url>` to its confirmation page, so the respondent books straight after the form. Each submission lands as a Wave-tab row with a fresh Tracking ID. Google Forms has no per-respondent gate; the researcher reads the answers after each submission.
- The `cancelled` status: the workspace participants-table vocabulary gains an eighth locked status beside identified, screened, invited, scheduled, completed, incentive-sent, and withdrawn. Its gate needs nothing, and it is allowed from any status at any time. A row leaves `cancelled` only through the recruit flow. Recruit step 12 reads the Tracking export CSV and marks the cancelled rows in both stores: lowercase `cancelled` on the workspace participants table, capital-C `Cancelled` on the spec roster through `roster_apply.py`. One re-invite nudge per cancelled row.
- Cross-calendar availability: `calendar_prep.py` accepts repeated `--dump <events.json>` inputs, one per calendar. The busy intervals are unioned before slot picking, so an availability check spans every project the researcher runs. The output shape is unchanged.
- The appointment-link runbook `references/checklists/appointment-link.md`: the computer-use runbook that creates a Google Calendar appointment schedule in the fewest clicks and ends with the link in the merge Sheet `booking_url` cell. Creation is UI-only; the Calendar API cannot create appointment schedules.
- Sheet export: `recruit_send.py --export-sheet <out.csv>` writes the external participants table to CSV under the `DEFAULT_WAVE_TAB_HEADERS` funnel columns. The merge Sheet's Wave tab must match the `google/README.md` shape; mapping the columns across is the researcher's step.
- The unsubscribe footer: when `recruit.email.unsubscribe` is on (the default) and `recruit.email.webapp_url` is set, every merged SMTP body gains one line that points at the web app unsubscribe route. Both keys ship in `config/org.example.yaml` with `UXR_RECRUIT_*` env fallbacks, and the draft-only default is untouched (the researcher runs the real send).
- The copy-and-go template sheet: `google/template-builder.gs` builds the master in one `buildTemplate` run (every tab, sample Wave rows, the SETUP checklist tab), and an `onOpen` "uxr mail merge" menu rides inside every `Make a copy` (simple triggers survive the copy without authorization) with `Run mergeSend`, `Run setupScreener`, and `Install syncEvents trigger`, so the whole workflow is human-reachable from the Sheet without opening the script editor. The SETUP tab orders the copy-owner steps: deploy the web app, fill Config, install the trigger, screener, test send. `google/README.md` documents the master-build and copy flow.

One MO-ruled append-only exception: A1.4 gains the format-law Source clause the confirmed line lacked, so the unchanged loader parses all 66 (`load_items` proof 5/29/32). The enrolled `checklist_gate` selftest reads the shipped-content law; the absent-line check rides an empty-directory override.
- The writing-rules registry `references/writing-rules.md` (#53): 26 seed rules in five families - universal (R-U, X-U), interview (R-I, X-I), survey (R-S, X-S), HCI (R-H), academic (R-A) - one line per rule, verbatim from law the plugin or MO already holds. Ids stable forever; appending never renumbers. Items and skills apply rules by id and never restate rule text.
- The survey skill `skills/survey-script/SKILL.md` (#53): the B1.4 counterpart of `skills/interview-script`, seven steps mirroring it on survey law - inputs (population, survey tool, data-join inventory), output path `survey-instrument-<KEY>.md` with the `-v2` rule, the research-question to question-type to engagement mapping, burden budget + routing map + two-to-five alternatives with kept winners + join and segmentation fields, question rules applied by registry id (R-S, X-S, R-H, R-A), the reader review loop ending in the new survey checker mode, and the save/report/ticket/publish laws.
- The survey mode of `scripts/review_checks.py` (#53): the four checks over the instrument shape - burden count (a section declares K questions, holds M; total against the `**Burden budget**` line), routing-map parse (every conditional question mapped, every landing real, no dead ends), coverage map (every RQ map row carries a survey question; warn), alternatives count (two to five per core question, kept winner recorded) - with the `check` exit law (0 clean, 1 warn, 2 unparseable, 3 block). `check` behavior and output are byte-identical.
- The autonomy switch (#53): `checklists.autonomy: execute | approve` (default `execute`) beside `checklists.enforcement`. `[human]` and `[draft]` items always pause for the human - the human keeps every critical decision; `[draft]` drafts when the context it needs is available in the workspace and never invents; `[human]` is never automated. `approve` additionally pauses at every group boundary, where the runner presents the group summary, the artifact links, and the missing list, and waits for one go-ahead word. The pause plan joins the gate loop: the output-only hierarchy attachment (the nearest `###` group and the `Executor:` default ride the item JSON; `ITEM_RE` and the parse unchanged; `check` and `citations` unchanged) plus the new CLI form `python lib/checklist_gate.py pauses --type <type> [--autonomy execute|approve] [--json]`. Shipped plans: A0 1/2, A 11/18, B 12/19 pauses.
- The method-selection artifact and the A0 entry stage (#53): `templates/workspace/method-selection.md` (the classification table on the attitudinal/behavioral and qualitative-direct/quantitative-indirect axes with context of use and time stage, the method with alternatives, the spec record, the routing line with the named-gap wording) lands in every new workspace through the scaffold; `uxr-init` step 7b syncs the canonical set (the three checklists + the writing-rules registry) into the workspace through the new `SYNC_SET`/`sync_references` plugin-to-workspace copy in `hooks/workspace_sync.py` (absent files copy, identical files stay, differing files stay as recorded local overrides; never clobbers, never deletes); and the `uxr-report` phase 0 gate runs the method-selection check before the type check with record-gap semantics - a method without a shipped checklist records its named-gap line and the study proceeds under the shared law.
- The content selftest `tests/uxr_selftests/checklist_content.py` (#53; outside the payload): the shipped loader finds exactly 5 / 29 / 32 items with the exact id sets in pipeline order, the tag counts are exactly 42/15/9, the optional markers are the exact confirmed set, every registry id an item names resolves, and the MO-banned artifact word has zero hits in the new content. Rides the smoke selftest glob; not enrolled in the parity SELFTESTS.

## [0.2.0] - 2026-11-18

### Changed

- Efficiency pass (W2): the golden path across the workflow now spends six model calls (evidence signals synthesis, one structured drafts call for the `new` interview's phases 3-5, report narrative, debrief summary, and one checklist-scoped HCD gate per artifact); every previously model-rendered mechanical step (mine/show tables, evidence plan and digest, RQ map, method pick, router intent, recruit slots and replies, review-finding routing, eod drafts) is script-owned and byte-parity gated against the baseline goldens.

### Added

- Lazy-fragment prompt registry (`lib/prompts.py`) with prompt assets under `prompts/` (`config-setup`, `new-intake`, `signals`, `drafts`, `hcd-gate`, `distribution`, `outreach`), each rendered from JSON front matter with condition-matrix fixtures and metering lines (`prompt_id@version fragments=[...] est_tokens=N`).
- Data-driven render helper (`lib/render.py`, CLI folded in W2b): mine table, show card, relative-time ladder, and emoji map are JSON specs in `prompts/render/`.
- Deterministic classifiers (`scripts/classify.py` + `prompts/classify/`): router intent, recruit reply classes, method-shape table, decision-shape gate, review-finding routing.
- Evidence sweep planner and digester (`scripts/evidence_sweep.py`): emits the per-source query plan and compresses raw results into the evidence digest the signals call consumes.
- Journal scripting (`scripts/eod_journal.py`): filter, cap check, facts-only `--auto` template, and the `processed` rewrite; `--polish` opts into one narrative rewrite per ticket.
- Slot picking (`scripts/calendar_prep.py --pick`): deterministic free-gap fits on a 15-minute grid with move candidates.
- RQ-to-hypothesis map with the drop rule (`scripts/trace_prompts.py --rq-map`).
- Scripted spec save/read-back (`scripts/backfill_spec.py save-spec|check-readback`) and debrief summary/recap assembly (`references/debrief_helpers.py assemble-summary|render-recap`).
- Golden parity gates: `tests/goldens/` (baseline artifacts, `DIFFERS`-marked where W1 changed behavior), hash pins, and the parametrized runner `tests/test_parity.py`, wired into the repo verifier.

### Removed

- The `/uxr-new` reference stack (`research-craft.md` deleted; its method table lives in `prompts/classify/methods.json`), the inline eod and new heredocs, the duplicated per-command configuration blocks (one canonical `config-setup` asset), and the duplicated relative-time ladder in `uxr-show`/`uxr-mine`.

## [0.1.0] - 2026-11-09

### Added

- Config contract: `config/org.example.yaml` documents every key; `lib/config.py` loads, merges, validates, and expands it, with a `--selftest`.
- Plugin skeleton: `.claude-plugin/plugin.json` manifest, `commands/` and `skills/` directories, and fail-open hook wiring in `hooks/hooks.json` (SessionStart, SessionEnd, SubagentStop, PreToolUse `Write|Edit`, UserPromptExpansion; missing scripts exit 0).
- SessionStart context hook `hooks/ux_research_context.py`: injects commands, tracker constants, and the routing note once, only inside research folders (research root from config or `UXR_RESEARCH_DIRS`, or `00-overview.md` in the cwd or a parent below `$HOME`); other events, including UserPromptSubmit, print nothing.
- All-local smoke gate `scripts/smoke_test.py`: version triple, command and skill minimums, per-script self-tests, schema checks, front matter with quoted descriptions, the no-tracker-writes rule for `scripts/`, and dash-free recruitment templates.
- CI: `.github/workflows/plugin-ci.yml` runs the smoke test on plugin-path changes plus a non-blocking `claude plugin validate` step.
